# The Outside plugin and the Plugin Hub: precedents

For submitting the Outside plugin (`plugin/`) to RuneLite's Plugin Hub (11/09/2026, Jace: "for every piece of info that we track, provide a plugin that already exists on the plugin hub ... if we have examples, it's harder for them to find something wrong with it"). For each piece of information the plugin reads or sends, the plugins already on the Hub (and in RuneLite itself) that read or send the same, with the exact lines a reviewer can check.

**How it was checked.** Every plugin below was read from its real source, at the commit its Plugin Hub manifest (`plugins/<name>` in [runelite/plugin-hub](https://github.com/runelite/plugin-hub), as of commit `a85ea39`, 11/09/2026) points to; RuneLite's own plugins at [runelite/runelite](https://github.com/runelite/runelite) commit `e7098b7`. Every link goes to that commit and line. Nothing here is from memory; anything that couldn't be confirmed is left out.

**A caution, in RuneLite's own words** ("Rejected or Rolled Back Features", the runelite wiki): "some older plugins are grandfathered into these rules. Just because an existing plugin does something in a certain way does not guarantee it is allowed." So these are support for the case, not a guarantee. The newest precedents (and RuneLite's own core plugins) carry the most weight.

## The rows a reviewer may ask about

Every row has a precedent; these are the ones with the narrowest:
- **Active prayers (row 7)** are kept (Jace, 11/09/2026: "the party hub transmits them and does that exact thing… seems like an odd place to draw the line given the live loadout plugin allows people using their plugin to transmit their entire bank"). RuneLite's own Party plugin sends exactly this, read the same way, to the other members of a party through RuneLite's server. No Hub plugin was found sending prayers to a third party, but Twitch Live Loadout sends far more to its viewers, the bank up to 5,000 items by default among it (row 26), and Outside's prayers go only with the vitals switch, and never from the Wilderness or a PvP world, where an attacker could use them.
- **The finder's name on a public star list (row 21):** opt-in, as Star Miners' is, and the outstation's name rather than the in-game name.
- **Activity published to anyone (rows 16-18):** RuneLite's Discord plugin is the precedent, but it shows to Discord friends, not to the public. GIM and TLL send more (the NPC and its health, fight statistics) to a website and to stream viewers.

## The licence, and the repository it's submitted from

What the Hub actually requires, from its packager ([Plugin.java](https://github.com/runelite/plugin-hub-tooling/blob/034eaffd5bce7bb678d35287b547874f3dba6b3b/package/src/main/java/net/runelite/pluginhub/packager/Plugin.java)):
- **A `LICENSE` file at the root of the repository** ([L1087-1095](https://github.com/runelite/plugin-hub-tooling/blob/034eaffd5bce7bb678d35287b547874f3dba6b3b/package/src/main/java/net/runelite/pluginhub/packager/Plugin.java#L1087-L1095)): "All plugins must be licensed under a license that allows us to freely distribute the plugin jar standalone. We recommend the BSD 2 Clause license." BSD 2-Clause is recommended (the README walks through choosing it), not required: any licence that lets them distribute the jar passes. MIT would too.
- **`runelite-plugin.properties` at the root of the repository** ([L435](https://github.com/runelite/plugin-hub-tooling/blob/034eaffd5bce7bb678d35287b547874f3dba6b3b/package/src/main/java/net/runelite/pluginhub/packager/Plugin.java#L435): "runelite-plugin.properties must exist in the root of your repo"), and the manifest takes only `repository`, `commit`, `warning`, `authors`, `jarSizeLimitMiB`, `disabled` and `unavailable` ([L249-306](https://github.com/runelite/plugin-hub-tooling/blob/034eaffd5bce7bb678d35287b547874f3dba6b3b/package/src/main/java/net/runelite/pluginhub/packager/Plugin.java#L249-L306)): there's no way to point it at a folder inside a repository. `repository=` must be an https GitHub clone URL ending in `.git`.

So the mixed licences aren't the problem; the layout is. This repository (MIT at its root, the plugin in `plugin/` under BSD 2-Clause) can't be submitted as it is: its root has no `runelite-plugin.properties`, and its root `LICENSE` would be the one the Hub reads. The plugin goes from a repository of its own (plugin/README.md already plans `jhmcubed/outside-plugin`), with `plugin/`'s files at its root and `plugin/LICENSE` (BSD 2-Clause) as its `LICENSE`. That repository then holds only BSD 2-Clause code (with Shooting Star Info's BSD 2-Clause notice kept in `Sites.java` and the README's Credits), and nothing in it is MIT. With `build=standard`, the Hub replaces its `build.gradle` and `settings.gradle` with its own.
